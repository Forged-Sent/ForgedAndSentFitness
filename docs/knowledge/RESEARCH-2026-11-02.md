# Research basis: agent memory and Flutter delivery

**Reviewed:** 2026-11-02. **Confidence:** official documentation for general guidance, repository inspection for project-specific context. This record proposes policies; it does not certify device builds or tooling handshake.

## Adopt
- Flutter recommends separation of UI/view models from repositories/services, immutable one-way state, dependency injection, unit/widget tests and conditional use-case layers. https://docs.flutter.dev/app-architecture/guide and https://docs.flutter.dev/app-architecture/recommendations
- Flutter officially supports Android, iOS, web, Windows, Linux and macOS, but platform SDK toolchains and plugin compatibility differ. https://docs.flutter.dev/reference/supported-platforms and https://docs.flutter.dev/platform-integration/desktop
- Official Flutter AI setup now includes agent skills/rules, local Dart MCP and Developer Knowledge MCP. Use official tooling when present; maintain project-specific security rules. https://docs.flutter.dev/ai/get-started and https://docs.flutter.dev/ai/tools
- Context7 recommends agent rules for automatic documentation retrieval and library/version-specific queries. Restrict its use to live API lookup, not permanent memory or bulk document copying. https://context7.com/docs/tips and https://context7.com/docs/api-guide
- Codex AGENTS.md, Claude CLAUDE.md and Gemini GEMINI.md are project instructions; keep shared rules in AGENTS.md and use adapters to prevent policy drift. https://learn.chatgpt.com/docs/customization/overview ; https://support.claude.com/en/articles/14553240-give-claude-context-claude-md-and-better-prompts ; https://geminicli.com/docs/cli/gemini-md/
- Flutter unit/widget/integration tests cover distinct risk classes; native integration and platform UX cannot be inferred from a Dart unit test. https://docs.flutter.dev/testing/overview

## Deliberately not adopted
- Automatic desktop host generation or release in this documentation-only PR; native toolchains, per-plugin support, signing and runtime tests are unverified.
- Copying large external rules or docs into agent startup prompts; they expand token costs and go stale. Prefer short routing files and on-demand skills.
- Autonomous PR merging, production credentials, automatic cloud Firebase MCP, unrestricted Obsidian MCP writes or auto-archive/deletion.
- Relying on multi-model consensus as a security proof. Independent reviews are advisory; deterministic CI and human control over sensitive changes remain necessary.

## Next research gates
1. Before desktop enablement: audit every dependency in pubspec.lock for supported platforms; then enable platform host and OS-specific CI individually.
2. Before meaningful prototype migration: approve a traceability/UX contract and define state management, durable local outbox and offline test plan.
3. Before production: review real Firebase rules/server trust boundaries, age/privacy requirements, release signing and device QA separately.
